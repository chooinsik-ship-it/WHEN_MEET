# 한글 단어 추리 게임 (언제만나 · 단어 게임 탭)

로그인 사용자별로 게임 기록을 서버에 저장하고, **전체 종합 랭킹**과 **출제 단어별 랭킹**을 제공한다.

## 1. 기존 구조와의 관계

| 항목 | 기존 프로젝트 | 게임에서 한 선택 |
|---|---|---|
| DB | RDB 없음. Upstash Redis(`@vercel/kv`) | 테이블·인덱스 대신 **Redis 키 설계**로 대체 (§3) |
| 인증 | 닉네임 해시 + 비밀번호 검증만, 세션 없음 | 로그인 성공 시 **HMAC 서명 세션 쿠키** 발급, 게임 API는 쿠키만 신뢰 |
| 사용자 표시 | 닉네임 + 이모지 아바타 (`user:<id>.avatar`) | 랭킹에 닉네임·아바타 표시 (프로필 이미지 기능이 없어 이모지 사용) |
| UI | `app/page.tsx` 단일 페이지 + 탭 | **"단어 게임" 탭** 추가, 내부에 게임/통계/랭킹 하위 탭 |
| 회원 상태 | 탈퇴·정지·비공개 정책 없음 | 연동할 정책이 없어 미구현 (§7 제한사항) |

## 2. 게임 규칙

`app/lib/wordgame/config.ts` 의 설정값으로 관리한다.

```
RULE_VERSION = 1      자모 칸 5칸      최대 5회 시도
RULE_ID = "v1-j5-a5"  ← 통계·랭킹 분리 키
```

- 정답을 기본 자모 24개(자음 14 + 모음 10)로 분해해 맞히는 방식
- 복합모음·쌍자음·겹받침은 기본 자모로 분해: `ㅐ→ㅏㅣ`, `ㅔ→ㅓㅣ`, `ㄲ→ㄱㄱ`, `ㄺ→ㄹㄱ` 등 (`app/lib/hangul.ts` `COMPOUND_JAMO`)
- 판정: **초록(위치까지 일치)을 먼저 확정**한 뒤, 남은 정답 자모 개수만큼만 노랑. 초과 중복은 회색
- 규칙이 바뀌면 `RULE_VERSION` 을 올린다 → `RULE_ID` 가 바뀌어 기존 기록과 절대 섞이지 않는다

## 3. 데이터 모델 (Redis 키)

모든 키가 `ruleId` 를 포함하므로 자모 칸 수·시도 횟수·규칙 버전이 다른 기록은 자동으로 분리된다.

| 키 | 타입 | 역할 (RDB 대응) |
|---|---|---|
| `wg:game:<gameId>` | JSON | 게임 1건 (games 테이블) |
| `wg:active:<ruleId>:<userId>` | string | 진행 중 게임 1개 제한 |
| `wg:first:<ruleId>:<userId>:<wordId>` | string (SET NX) | **최초 도전 유니크 제약** |
| `wg:played:<ruleId>:<userId>` | set | 이미 출제된 단어 (미출제 우선 선정용) |
| `wg:recent:<ruleId>:<userId>` | list | 직전 출제 단어 (반복 방지) |
| `wg:hist:<ruleId>:<userId>` | list | 개인 플레이 기록 (최신 300건) |
| `wg:uwords:<ruleId>:<userId>` | list | 최초 도전이 끝난 단어 = 단어별 랭킹 열람 권한 |
| `wg:wordres:<ruleId>:<wordId>` | list | 단어별 최초 도전 결과 |
| `wg:agg:<ruleId>:<bucket>:<userId>` | JSON | 기간별 집계 (랭킹 인덱스 역할) |
| `wg:aggidx:<ruleId>:<bucket>` | set | 버킷별 사용자 인덱스 |
| `wg:idem:<gameId>:<requestId>` | JSON, TTL 1h | 제출 멱등성 |
| `wg:lock:*` | string, TTL | 동시성 제어 |
| `wg:rate:*` | counter, TTL | 요청 제한 |
| `wg:session-secret` | string | 세션 서명 키 (자동 생성) |

`bucket` = `all` / `d:YYYY-MM-DD` / `w:<그 주 월요일>` / `m:YYYY-MM` (모두 **Asia/Seoul** 기준)

> **마이그레이션은 필요 없다.** Redis 키는 첫 사용 시 생성된다.
> 규칙을 바꾸면 새 `RULE_ID` 로 키가 새로 쌓이므로 기존 기록은 그대로 보존된다.

## 4. 집계 기준

- 종료 게임 = SUCCESS + FAILED + ABANDONED, 성공률 = 성공 / 종료 게임 (진행 중은 분모 제외)
- 평균 시도·평균 시간은 **성공한 게임만** 대상, 기록이 없으면 `null` → 화면에 "기록 없음"
- 실패·포기는 연속 성공을 끊는다
- 시작 게임 수는 **시작 시각** 기준 버킷, 나머지는 **종료 시각** 기준 버킷
- 소요 시간은 서버 시간 기준 `종료 - 시작` (페이지를 닫고 있던 시간도 포함)
- 반복 플레이도 개인 통계·종합 랭킹에 모두 집계된다 (화면에 안내 문구 노출)
- 단어별 랭킹은 **사용자별 최초 도전 1건만** 반영. 최초 도전이 실패·포기면 재도전으로 진입할 수 없다

## 5. 정답 노출 방지

- 게임 시작·진행 중 응답에 정답과 `wordId` 를 넣지 않는다 (`toPublicGame`)
- 사전은 `app/lib/wordgame/dictionary.ts` — **서버 라우트에서만** import (클라이언트 번들에 없음)
- 단어별 API는 "그 사용자의 최초 도전이 **끝난** 단어"만 허용, 그 외에는 사전 존재 여부도 구분되지 않게 동일한 403 반환
- `/api/word-games/me/words` 는 이미 끝낸 단어만 돌려준다 → 사전 전체를 훑을 수 없다

## 6. 실행 · 테스트

```bash
npm run dev             # 개발 서버
npm run build           # 프로덕션 빌드(타입 체크 포함)
npm run test:wordgame   # 순수 로직 단위 테스트 (node --test, 38개)
```

로컬에서 게임을 돌리려면 KV 환경변수가 필요하다.

```bash
npx vercel login && npx vercel env pull
```

환경변수가 없으면 게임 API는 503을 반환한다(기존 시간표 기능은 로컬 폴백으로 계속 동작).

## 7. 단어 사전 교체 방법

`app/lib/wordgame/dictionary.ts` 의 `WORDS` 배열은 **샘플**이다(직접 선별한 일상 명사 약 360개,
그중 자모 5칸에 해당하는 132개가 실제 출제 후보). 운영용 사전이 아니다.

교체하려면:

1. 라이선스를 확인한 출처의 단어 목록을 확보한다
   (예: 국립국어원 *우리말샘* — 배포 조건 확인 필요)
2. `WORDS` 배열을 그 목록으로 교체한다. 자모 길이는 신경 쓰지 않아도 된다 —
   `buildEntries()` 가 현재 규칙(`JAMO_COUNT`)에 맞는 단어만 자동으로 추린다
3. `npm run test:wordgame` 으로 모든 단어가 규칙과 맞는지 확인한다
4. **단어 ID 는 단어 문자열의 SHA-1** 에서 생성되므로, 사전에 단어를 추가·삭제해도
   기존 단어의 랭킹은 그대로 유지된다

## 8. 알려진 제한사항

- **사전이 샘플**이라 정답 후보가 132개뿐이다. 반복 플레이하면 같은 단어가 다시 나올 수 있다(의도된 동작).
- 입력 검증 사전도 같은 132개 단어를 쓴다. 정답 후보보다 넓은 "허용 입력 사전"이 필요하면
  `dictionary.ts` 에 별도 목록을 추가해 `findByJamo` 에서만 사용하도록 분리하면 된다.
- 랭킹은 버킷별 사용자 인덱스를 모두 읽어 메모리에서 정렬한다. 개인 프로젝트 규모(수백 명)에는 충분하지만,
  수만 명 규모가 되면 Redis Sorted Set 으로 옮겨야 한다.
- 집계는 게임 종료 시점에 여러 키를 갱신한다. 게임 종료 플래그(`aggregated`)로 중복 집계는 막지만,
  집계 도중 프로세스가 죽으면 일부 버킷이 누락될 수 있다(재계산 도구 없음).
- 회원 탈퇴·정지·비공개 정책이 프로젝트에 없어 랭킹 노출 제어를 연동하지 못했다.
- 부정행위 자동 차단은 하지 않는다. 요청 제한과 서버 판정만 적용한다.
